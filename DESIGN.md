# Desktop design contract

Mode: Operate. Preserve the dashboard's Survey Sheet design.

The Reoclo web dashboard's design system and its Button, Input, Table, StatusBadge, InfoField and PageHeader components are the visual authority. The desktop translates their semantic tokens into Rune, rather than treating the native app as a website.

- Light: paper background, deeper paper sidebar, ink foreground. Dark: night chart background with warm light foreground.
- One-pixel rules separate surfaces. No shadows. Corners use 2, 3 and 4 point radii.
- Figtree for controls and prose, Mona Sans for page titles, JetBrains Mono for machine values. Embedded font assets retain their licenses.
- Spacing: 4, 8, 12, 16, 24, 32 points. Body 14 points, labels 12, section headings 18, page titles 28.
- Status: square success for Active, triangular warning, circular information, diamond failure, filled neutral dot for Ready, and an outlined neutral ring for inactive states. Ready means listening without an open session. Every mark has a text label.
- Four button ranks: primary (flat foreground/background contrast), secondary (a one-point rule), danger (a one-point danger rule, for an action that opens a confirmation), and destructive (filled danger, only for the button that confirms). Offer the action the current state allows rather than disabling the others. In a dialog the primary action is rightmost, with Cancel to its left. Orange belongs to selection and focus. Destructive actions require explicit confirmation.
- Theme follows the system unless the user chooses light or dark. Motion uses Rune's virtual clock and reduced-motion support.

Layout: Main window uses a split view with sidebar navigation, a toolbar, and one scrolling content region. The tunnels table owns its row scrolling and sizes to its rows up to eight; each row has its own toggle, because bringing a tunnel up is the primary action. The selected tunnel's details follow below the table. Pending approvals sit above the table, because an agent is blocked on them. Tunnels running in a terminal sit between them, with their real ports and a confirmed Stop, and they show even with no saved tunnels. A TCP forward or saved TCP tunnel offers Add HTTPS, which opens the Add tunnel form prefilled for the same target. No horizontal overflow at the minimum supported desktop size.

Layout: Add tunnel is a modal form with a single scrolling body and visible Cancel and Save actions. Organization selects the server list; server selects the scanned ports. The manual target remains available.

The form is two columns and fits without scrolling in its usual state, with Kind first because it decides the rest. The HTTPS hostname preview stays outside the scrolling form body. A fading edge and native scrollbar reveal overflow when a warning or error adds height. Kind labels are uppercase; the wire values remain lowercase. Selects and inputs share one height and rule. An HTTPS hostname is an optional subdomain on a trusted domain chosen from a list; without a trusted CA the form offers to trust it and stays open so it can be saved next. Certificates trusts another domain, and Hosts registers and removes hostnames of your own. The port 443 relay has a switch that reinstalls the helper after a confirmation, and says when another program holds port 443. Every helper reinstall keeps the relay and the trusted domains outside .localhost. A trusted domain you added has Remove, which reissues the CA without it after a confirmation; a stale CA offers Trust new CA. Form dropdowns can be searched, and every floating menu has a one-point rule so it reads against the surface it opens over.

Layout: Menu-bar panel is 340 points wide with one scrolling list and a fixed footer. Approvals precede server groups. Each tunnel takes two lines: name, state, icon actions and toggle, then the endpoint across the full width. The panel header carries the mark and the wordmark, followed by the active count and a diamond with the failure count. A failed row shows its reason in place of its endpoint. Tunnel names open the window with that tunnel selected. Open buttons keep a reserved slot and only appear for Active or Ready tunnels. The menu bar item follows a setting: icon, icon and name, icon and active count, or icon and a meter of one bar per tunnel. Pending approvals and a failure flag show in every style. Meter bars are solid for active tunnels, short stubs for enabled failures, and outlined otherwise.

Layout: Get started is a modal over the main window, shown on first launch and from Settings as Run setup again. Two required steps, Background service and Sign in, precede the optional Secure web addresses section. Each has a status mark and one secondary action. The sign-in step shows the device code and Open sign-in page in place. Headings use plain words, with terms such as daemon and CA kept to body text. Done is the primary action and sets the onboarded preference; closing it any other way leaves the screen to return next launch.

Layout: A `reoclo://open` link always opens a confirmation first, saying what will be reached, on which server, in which organization, and as HTTPS or a local port. Cancel drops it. Confirm signs in if needed, checks the organization and server, reuses a saved tunnel for the same server, kind and target or adds one, then opens the HTTPS address or copies the TCP endpoint. A tunnel that is Ready or Active counts as reached. Invalid links show an alert and change nothing.

Priorities: tunnel state and endpoint first, server and transport second, traffic and diagnostics third. No decorative metrics or promotional copy. Required data remains present through empty, loading, disconnected, signed-out and error states.

The sidebar is the main window's only product wordmark, and it carries the hexagon mark. The toolbar reserves its trailing slot for real status: a disconnected daemon, work in progress, or the last confirmation. Failures appear under the page title, where they cannot be scrolled past. Mono is for machine values, never prose. Status words always carry their mark. The selected table row and sidebar use the same selection token. Switches describe saved intent: the column is "On" and the accessible label is "Run <name>". They use a light thumb in both appearances, on a track at least 3:1 against it.

Native desktop acceptance: window at 1100 x 760 and minimum 760 x 620; panel at 340 x 620. A 390 point compact capture checks narrow content behavior, but this is not an iPhone app and mobile safe areas do not apply. Light and dark are captured for every required view and state. Rune PNGs and element trees are the visual evidence; browser-only detectors do not apply to the native renderer.

Updates: Settings places Updates before Desktop app, using the existing setting rows and semantic status marks. Current version and last-check time remain visible beside Check now or Restart to update. Automatic checks default on and persist in the app preferences. A download is labelled as downloading until its SHA-256 and Ed25519 signature pass and the extracted bundle version matches. Ready updates include release notes. Update failures stay in this section without an alert dialog. Outside a writable app bundle, the section explains why updates are off.

Updates: The panel adds one fixed row above its footer only for a verified update, with the version and Restart. It stays quiet during checks and failures. Restart always requires a click. The app stages the replacement on its own volume and waits for the current process to exit before swapping bundles and opening the new copy. A failed relaunch restores the previous bundle. Tunnels keep running in the daemon.

Updates: Settings remains accessible when the daemon is disconnected. Its loading layout keeps the live Updates section because desktop update state does not depend on daemon data. Capture update-available and update-ready in both themes for Settings and the panel, including compact widths. Interaction tests exercise the automatic-check switch and both restart buttons.

Layout: Tunnels pins its title and two-part summary above its scroll view. The summary is "N of M active", with a diamond and "N failed" when needed. Identical failure details shared by at least two tunnels produce one pinned alert and a group retry. HTTPS port conflicts offer Settings with the port field focused. The table columns are State, Name, Server, Endpoint and On. State is 148 points; Name and Server fit their values between 96 and 220 points, sharing the available width at the minimum window; Endpoint takes the remainder with a 160 point minimum. Sorting happens only when requested, never on state updates. Server names use middle truncation with a full-value tooltip.

Layout: Non-listening tunnel details place the reason and recovery actions before facts. The reason appears once, in its alert. A subtitle appears only when the daemon's message adds information beyond that alert and the state badge; the loading skeleton follows the same subtitle rule. Open is offered only for Active and Ready; Copy endpoint remains available. Zero traffic and streams read "No traffic yet". Facts use up to four 200 point columns, left aligned, with two columns in compact windows. Daemon events name only the selected tunnel and include the UTC arrival time.

Layout: Tunnels, Hosts, Certificates and Settings cap content at 1200 points. Below 900 points the sidebar collapses and page padding becomes 16 points. Compact terminal rows disclose their forwards on request. The loading skeleton includes the Tunnels summary and Add tunnel control, and follows the content cap and compact padding.

Layout: Offline, signed-out and error views retain cached tunnels as Unknown with switches hidden. Offline names the attempted socket and offers Copy details. Error names tunneld.log and offers Show log in Finder. First launch without cached rows uses the empty data-state layout. Signed out appears in the toolbar. Approvals show a sentence-case action label and expiry, with Deny before Approve; only the pending control is disabled. Action labels support the daemon's open string vocabulary, including unfamiliar values. Actions reaching beyond this Mac retain the warning tone. Page and dialog titles expose heading roles. Blocking data states expose alert roles.
